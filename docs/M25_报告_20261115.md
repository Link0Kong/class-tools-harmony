# M25 报告 — 诊断上报（client_diag）（2026-11-15 第 25 轮）

## 本轮交付

| 模块 | 内容 |
|---|---|
| 上报行 | `DiagReport.build`：仅当存在「注意/异常」检查时生成 `client_diag` 行（kind=diag、level=error/warn、title=异常项、fingerprint=异常 id 排序去重、detail.check=单项 id 或 multi + items 明细），**不含账号/路径/URL** |
| 节流 | `DiagThrottle`：同指纹 10 分钟窗口；`DiagReportStore` preferences 持久化上次上报时间（键 `last_report`） |

| UI | 本机检查卡标题行「上报异常」（仅存在异常时显示）→ 上报结果提示（成功/10 分钟节流/失败） |
| 规模 | 主代码 108 文件 / 20,967 行；测试 27 文件 / 4,257 行；HAP **2,830,992 B**；单测 **331/331** |

## 模拟器实测

- 本机检查通过 6 / 注意 0 / 异常 0 → 「上报异常」按钮按设计隐藏（无异常不上报）
- 上报链路（payload 构造、节流、POST、结果提示）由单测覆盖；当前模拟器环境健康，无法自然产生异常

## 已知限制

- 「上报异常」入口只按**本机检查**（6 项）判定；服务健康列表里的「注意/异常」项暂不进入上报 payload（buildFromRows 待补）。
- 修复动作（触发 `repair_tasks`）仍需本机代理执行，客户端只上报；无「AI 分析」触发按钮。
- 未采集内存/网络类型/时钟偏差等安卓 10 项全量，仍为 6 项。
- 上报节流按指纹（异常项集合），不同异常可各自 10 分钟一次；未做服务端配额校验。
